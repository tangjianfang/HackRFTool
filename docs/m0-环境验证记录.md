## 已知问题与规避方法（重要）

**每次插入 USB 后自检失败**（FPGA configuration FAIL、MAX2831 RSSI mux FAIL、后续测试全 SKIP）。

- 根因：HackRF Pro 固件已知 bug，上电时 FPGA 自加载失败（官方 issue
  [greatscottgadgets/hackrf#1696](https://github.com/greatscottgadgets/hackrf/issues/1696)，
  真机同样复现；官方已提供测试版修复固件，待正式版发布后再升级）
- 规避：**每次插入设备后先执行一次软复位**，自检即恢复全绿：

  ```sh
  hackrf_spiflash -R
  ```

- 复位后用 `hackrf_debug -t` 复核，应显示 `Self-test result: PASS`

## 验证步骤与结果

1. `hackrf_info`：设备识别正常，能读到板型/固件/序列号
2. `hackrf_spiflash -R` 后 `hackrf_debug -t`：**全部 PASS**（Mixer / Clock / MAX2831 / FPGA 配置 / FPGA SPI / SGPIO RX / Loopback）
3. `hackrf_transfer -r /tmp/hackrf_smoke.cs8 -f 100000000 -l 32 -g 32 -s 8000000 -n 8000000`
   （100 MHz FM 广播频段，8 Msps，1 秒）
   - 文件 16,000,000 字节 = 8M 样本 × 2 字节（I/Q 各 8 bit），无丢帧
   - 样本统计：满量程 0–255、均值 126.4、标准差 103.9 → 真实射频信号（增益饱和，
     正式使用时 `hackrf_transfer` 的 `-l/-g` 需下调）

## 其他注意事项

- USB 总线上另有 6 个设备：高采样率（≥16 Msps）时可能丢帧，必要时换直连主板的后置 USB 口并减少同总线设备
- 资料库（K3）中的固件 2022–2024 版**不适用于本设备**（HackRF Pro/Praline 平台为 2026 年新品，旧固件不支持）
