## 验证结果

- 单元测试：`ctest -R HackRFToolTest`——FFT（直流/单频/Parseval）、分析器（峰位 ±2 bin、峰电平 -2 dBFS ±1、峰值保持）、瀑布（环形/预填/长度校验）全部通过，`/W4` 零告警
- 真机冒烟：0.5 秒收 19.9 MB（≈40 MB/s 满速率，76 块无丢失）
- 真机 UI：接收 2450 MHz / 20 Msps / LNA 32 / VGA 30，频谱双曲线（实时+峰值保持）真实起伏，瀑布 64 行彩色历史，可辨 6-9 个 WiFi/蓝牙突发红色条带；状态栏帧计数确认数据流动（约 12 fps 构帧）

## 开发中的重要发现（备忘）

1. **WinFlux 布局**：容器必须 `align = stretch`，否则纯 `paint` 卡片宽度塌 0；根节点须设 `background`（无背景时脏区跟踪异常，瀑布曾因此不滚动）
2. **WinFlux `button()` 不带默认底色**（白字），必须显式 `background/text_color`（参照 Gallery 的 `button_primary` 模式）
3. **libhackrf 动态加载**：`hackrf_error_name` 等全部函数都要走 GetProcAddress，头文件路径是 `<libhackrf/hackrf.h>`（MSYS2 ucrt64）
4. **HackRF Pro 复位后需等 1-2 秒**再 `hackrf_open`（USB 重新枚举）
5. `add_subdirectory` 的 `CMAKE_MODULE_PATH` 不回传父作用域，WinFlux 的 cmake/ 须自己挂

hackrf_spiflash -R          # 每次插设备后先软复位（M0 已知固件 bug）

out/build/x64-debug/Debug/HackRFTool.exe auto   # 启动即接收（自动化验证用）
