# M3 交付记录

- 日期：2026-09-05
- 结论：**通过（试验性里程碑）**。F3 离线链路全部打通：IQ 采集 → 突发检测 → GFSK 解调，真机实测识别出环境 WiFi 信标指纹。

## 交付内容

| 模块 | 文件 | 说明 |
|------|------|------|
| GFSK 解调 | `src/dsp/gfsk.{hpp,cpp}` | 瞬时频率 → 符号窗均值 → 硬比特 + 置信度；**合成 GFSK 往返 BER=0**（测试自带 BT=0.5 高斯调制器） |
| 突发检测 | `src/dsp/burst_detector.{hpp,cpp}` | 滑窗能量 dBFS → 阈值连通段合并（间隙 <2 窗） |
| IQ 录制 | `src/radio/iq_recorder.{hpp,cpp}` | USB 回调线程有界队列（64 块满丢最旧计数）+ 独立写线程，stop 冲刷 |
| 采集工具 | `tools/iq_capture.cpp` → `HackRFCapture` | `HackRFCapture <out.cs8> <秒> [MHz] [lna] [vga]` |
| 分析工具 | `tools/gfsk_analyze.cpp` → `HackRFAnalyze` | `HackRFAnalyze <file.cs8> [阈值dB] [fs] [符号率]`；输出突发表（start_us/len_us/peak_db）+ 每突发比特数与前 16 字节 hex |

## 真机实验（2026-09-05，2450 MHz / 20 Msps）

第一次采集（LNA32/VGA30）：**增益饱和**——整段被判为单个突发、峰值 -0.8 dBFS。
降为 **LNA 8 / VGA 8** 后（197,132,288 字节 / 752 块 / 0 丢弃 / 4.928 秒）：

```
阈值 -40.0 dB 检出 56 个突发（节选）：
   #     start_us     len_us  peak_db
   1      13190.4     3315.2    -32.7
   2     115232.0     3340.8    -32.5
   3     217388.8     3353.6    -32.3
   4     319507.2     3328.0    -32.4
   5     421433.6     3353.6    -32.4
```

**发现：突发间隔 ≈ 102.4 ms、单个时长 ≈ 3.3 ms——WiFi AP 信标的标准指纹**（默认信标周期即 102.4 ms）。环境 2.4G 活动被完整捕获。

GFSK 比特列在 WiFi 突发上多为 0xFF——符合预期（WiFi 是 OFDM，FM 鉴频输出无意义；该列只对蓝牙 BR / nRF24 类无线键鼠突发有意义）。

## 使用指引（抓自家鼠标/键盘）

```sh
hackrf_spiflash -R
HackRFCapture mouse.cs8 10 2450 8 8     # 采集时持续移动无线鼠标
HackRFAnalyze mouse.cs8 -40             # 对比静默时段：多出来的短突发即鼠标流量
```

## 经验与结论（评估实时化）

1. **录制增益必须低**（本次 8/8 合适）：默认 32/30 时域即满量程，突发检测失效。M1 频谱页默认增益偏高的问题一并记录
2. µs 级时间分辨足够识别 102.4ms 信标周期类指纹；突发检测窗口 256 样本（12.8µs）合适
3. 实时化路径清晰：突发检测器可直接搬进 UI 线程（对 SpectrumFrame 或滑动 IQ 缓冲），GFSK 解调按需对突发段执行——**可行性验证通过，实时化为 M4 候选**
4. 协议级 framing（前导码/地址/CRC 解析）不在 M3 范围，需要目标协议样本

## 已知问题

- `HackRFCapture` 的 argv 路径按 ASCII 处理（中文路径可能异常）；建议输出文件名用英文
- 突发"包边界"是能量意义的边界（±1 能量窗），非协议帧边界
